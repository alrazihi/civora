# Stage 3: Evidence Document Intelligence

## Status: Complete

## Overview
Document attachment support for evidence — users can upload documents (PDFs, images, text, etc.)
to evidence records. Documents are stored with server-generated storage keys, content type
validation, checksum verification, and size limits.

## Architecture Decisions

1. **StorageProvider abstraction** — `internal/evidence/infrastructure/storage/storage.go`
   provides the `StorageProvider` interface (`Store`, `Retrieve`, `Delete`) with a
   `LocalStorageProvider` implementation backed by the local filesystem.

2. **Server-generated storage keys** — The service calls `GenerateStorageKey` to create
   keys in the form `YYYY/MM/DD/<evidence-uuid><ext>`. Path traversal is prevented via
   `SanitizeFileName` (uses `filepath.Base`, strips `..`, removes control chars) and
   `Retrieve`/`Delete` validate the cleaned path stays within `rootDir`.

3. **Content type allow-list** — `AllowedContentTypes` maps permitted MIME types.
   `ValidateContentType` strips charset suffixes and lowercases before checking.

4. **Checksum + size verification** — On store, `io.TeeReader` computes SHA-256 while
   writing. The declared `size` is checked against bytes actually written.

5. **Document domain entity** — `internal/evidence/domain/document.go`:
   - `Document` struct with internal-only `StorageKey` (json:"-")
   - `NewDocument` validates all required fields
   - `StorageProvider` enum: LOCAL, S3, GS, AZURE

## Migration
- `0033_evidence_documents.up.sql` — Creates `evidence_documents` table with foreign keys
  to `evidence` and `users`, content type CHECK constraint, unique storage key index.
  Also extends `audit.audit_events` action vocabulary with `evidence.document_uploaded`
  and `evidence.document_downloaded`.
- **Bug fixed**: Initial migration used `||` (string concat) in a CHECK constraint with
  `~` (boolean regex match). PostgreSQL rejects CHECK expressions that aren't boolean.
  Replaced with `OR` between independent `~` expressions.

## Service Layer
`internal/evidence/application/service.go` — `NewEvidenceService` now accepts a
`storage.StorageProvider`. Document methods:
- `UploadDocument` — validates, sanitizes filename, generates key, stores, creates Document, audits
- `GetDocumentStream` — validates access, retrieves from storage, returns stream + metadata
- (future: `DeleteDocument`, `ListDocuments`)

## API Layer
`internal/evidence/api/handler.go` — Routes registered for upload/download:
- `POST /organizations/{org}/evidence/{id}/documents` → UploadDocument
- `GET /organizations/{org}/evidence/{id}/documents/{doc}/download` → GetDocumentStream
