## 2. Attack Methodology

This review applies adversarial testing against the operations module attack surface. Testing is performed by static code inspection, architectural analysis, and regression test coverage review.

### 2.1 Attack Categories Tested

1. Authorization bypass (missing role gate)
2. Cross-tenant data leakage
3. PII leakage in metrics responses
4. Aggregation/minimum group size bypass
5. AI prompt injection via query parameters
6. Date-range abuse / unbounded bucket queries
7. Excessive AI input length
8. Bucket validation evasion

---

## 3. Findings

### 3.1 RESOLVED: Authorization Bypass — Missing Role Gates

| Field | Value |
|---|---|
| Severity | HIGH |
| Status | RESOLVED |

**Finding:** The operations endpoints (`/operations/metrics/*`, `/operations/analysis/*`, `/operations/impact/*`, `/operations/intelligence`) were missing `RequireAnyRole("admin", "staff")` middleware, allowing any authenticated user (including viewers) to access sensitive operational data.

**Evidence:**
- `internal/operations/api/handler.go:46` — Added `RequireAnyRole("admin", "staff")`
- `internal/operations/api/analysis_handler.go:26` — Added `RequireAnyRole("admin", "staff")`
- `internal/operations/api/impact_handler.go:24` — Added `RequireAnyRole("admin", "staff")`
- `internal/operations/api/ai_intelligence_handler.go:45` — Added `RequireAnyRole("admin", "staff")`

**Impact:** Unauthorized role access is now blocked at the middleware layer before business logic executes.

---

### 3.2 RESOLVED: PII Leakage in Metrics Responses

| Field | Value |
|---|---|
| Severity | HIGH |
| Status | RESOLVED |

**Finding:** `AgingCaseMetric` and `ThresholdExceedanceObservation` domain structs contained PII fields (`CaseID`, `CaseNumber`, `CreatedAt`, `UpdatedAt`) that were serialized in API responses.

**Evidence:**
- `internal/operations/domain/metrics.go` — Removed `CaseID`, `CaseNumber`, `CreatedAt`, `UpdatedAt` from `AgingCaseMetric`
- `internal/operations/domain/analysis.go` — Removed `CaseID`, `CaseNumber`, `CreatedAt`, `UpdatedAt` from `ThresholdExceedanceObservation`
- `internal/operations/infrastructure/postgres/metrics_repository.go` — Removed PII columns from queries
- `internal/operations/infrastructure/postgres/analysis_repository.go` — Removed PII columns from threshold query

**Impact:** PII is no longer exposed through operations metrics APIs.

---

### 3.3 RESOLVED: Aggregation Leakage — No Minimum Group Size

| Field | Value |
|---|---|
| Severity | MEDIUM |
| Status | RESOLVED |

**Finding:** Aggregated metrics could return groups with count < 5, potentially allowing inference of individual case data through repeated queries.

**Evidence:**
- `internal/operations/domain/metrics.go` — Added `MinimumAggregationGroupSize = 5`
- `internal/operations/infrastructure/postgres/metrics_repository.go` — Added `HAVING COUNT(*) >= $4` filters to all aggregation queries

**Impact:** Aggregation outputs now enforce a minimum group size of 5.

---

### 3.4 RESOLVED: AI Prompt Injection via Query Parameter

| Field | Value |
|---|---|
| Severity | HIGH |
| Status | RESOLVED |

**Finding:** The `question` query parameter in `/operations/intelligence` was passed unsanitized to the AI provider, enabling prompt injection attacks.

**Evidence:**
- `internal/operations/api/ai_intelligence_handler.go:18-31` — Added `sanitizeQuestion()` function that strips control characters and enforces max length of 2000 chars
- `internal/operations/api/ai_intelligence_handler.go:64` — `req.Question = sanitizeQuestion(r.URL.Query().Get("question"))`

**Impact:** Malicious instructions in the `question` parameter are neutralized before reaching the AI provider.

---

### 3.5 RESOLVED: Date-Range Abuse — Unbounded Bucket Queries

| Field | Value |
|---|---|
| Severity | MEDIUM |
| Status | RESOLVED |

**Finding:** The `bucket` query parameter accepted any date without bounds, enabling historical data scraping and future-date queries.

**Evidence:**
- `internal/operations/api/handler.go:66-80` — Added `validateBucket()` with `MaxBucketLookback = 2 * 365 * 24 * time.Hour` and `MaxBucketForward = 24 * time.Hour`
- `internal/operations/api/handler.go:94-107` — `parseBucket()` returns `time.Now().UTC()` when bucket is empty, and validates bounds when provided
- `internal/operations/api/ai_intelligence_handler.go:73-84` — Added bucket validation for intelligence requests
- `internal/operations/api/impact_handler.go:47-51` — Added bucket validation for impact reports

**Impact:** Bucket queries are now bounded to ±2 years lookback and +1 day forward.

---

### 3.6 VERIFIED: Cross-Tenant Access Control

| Field | Value |
|---|---|
| Severity | HIGH |
| Status | VERIFIED |

**Finding:** All operations endpoints enforce `RequireSameTenant` middleware, ensuring users cannot access data from other organizations.

**Evidence:** Regression test `TestMetricsSecurity_CrossTenantBlocked` verifies 403 response when token orgId mismatches path orgId.

**Impact:** Cross-tenant isolation is maintained.
