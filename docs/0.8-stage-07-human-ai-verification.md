## Status: GO

## 1. Overview

This document describes the human verification lifecycle for AI-generated information implemented in Stage 7 of CIVORA 0.8. The system ensures that AI-generated information does not silently become trusted case information. Human verification must be explicit, auditable, and tracked with full provenance.

When an AI observation is accepted or corrected, a **verified fact** is created with full provenance tracking, preserving:

- original AI output
- human action (accept, reject, correct, dismiss)
- corrected value (if applicable)
- actor
- timestamp
- source
- model/provider

## 2. Lifecycle

### 2.1 Observation Lifecycle

```
OPEN -> ACCEPTED -> VERIFIED FACT CREATED
       REJECTED
       CORRECTED -> VERIFIED FACT CREATED (HUMAN_CORRECTION)
       DISMISSED
```

### 2.2 Verified Fact Creation

When an observation is reviewed, the system creates a verified fact with the following provenance:

```json
{
  "source": "HUMAN_ACCEPTED",
  "original_source": "AI_OBSERVATION",
  "verified_by": "reviewer-uuid",
  "verified_at": "2026-09-17T17:00:00Z",
  "model": {"name": "gpt-4o-mini", "version": "1.0", "provider": "openai"},
  "references": [{"type": "evidence", "id": "evidence-uuid"}],
  "metadata": {
    "review_action": "ACCEPTED",
    "review_notes": "Observation is accurate"
  }
}
```

### 2.3 Provenance Fields

| Field | Description |
|-------|-------------|
| **source** | HUMAN_ACCEPTED, HUMAN_CORRECTION, AI_OBSERVATION |
| **original_source** | Always AI_OBSERVATION |
| **verified_by** | Human reviewer UUID |
| **verified_at** | Timestamp of verification |
| **model** | AI model info |
| **references** | Source references (evidence, forms, documents) |
| **metadata** | Additional metadata |

## 3. Data Model

### 3.1 Verified Fact Entity

```go
type VerifiedFact struct {
    ID              uuid.UUID
    OrganizationID  uuid.UUID
    CaseID          *uuid.UUID
    ObservationID   uuid.UUID
    Type            ObservationType
    Value           map[string]any
    OriginalValue   map[string]any
    CorrectedValue  map[string]any
    Provenance      *Provenance
    ReviewAction    ObservationStatus
    ReviewerID      uuid.UUID
    ReviewNotes     string
    CreatedAt       time.Time
    VerifiedAt      time.Time
    Source          string
    Model           *ModelInfo
    InputHash       string
    OutputHash      string
}
```

### 3.2 Provenance Entity

```go
type Provenance struct {
    Source         string
    OriginalSource string
    VerifiedBy     uuid.UUID
    VerifiedAt     time.Time
    Model          *ModelInfo
    References     []SourceReference
    Metadata       map[string]any
}
```

### 3.3 Validation Rules

- `OrganizationID` required (non-nil UUID)
- `ObservationID` required (non-nil UUID)
- `ReviewerID` required (non-nil UUID)
- `Type` must be one of the 7 allowed observation types
- `Value` size ≤ 100,000 bytes
- `Source` must be one of: AI_OBSERVATION, HUMAN_CORRECTION, HUMAN_ACCEPTED
- `ReviewAction` must be one of: ACCEPTED, REJECTED, CORRECTED, DISMISSED
- `InputHash` and `OutputHash` required for reproducibility
- `Provenance` automatically generated with reviewer and timestamp

## 5. Security

### 5.1 Authorization

All endpoints require:
1. `AuthRequired` — valid JWT
2. `RequireSameTenant` — JWT org_id matches URL org_id
3. `RequireAnyRole("admin", "staff")` — authorized role
4. Service-layer `UserChecker.BelongsToOrganization` — double-check

### 5.2 Tenant Isolation

- All database queries scoped by `organization_id`
- Verified facts created only from tenant-scoped observations
- No cross-tenant data leakage possible

### 5.3 Historical Integrity

- Original AI output preserved in `OriginalValue`
- Human corrections preserved in `CorrectedValue`
- AI history never silently overwritten
- Provenance tracks all human actions

### 5.4 IDOR Prevention

- All lookups scoped by `organization_id`
- Reviewer must belong to organization
- Observation existence verified before fact creation

## 8. Security

### 8.1 Historical Integrity

The system enforces historical integrity by:

1. Preserving original AI output in `OriginalValue`
2. Preserving human corrections in `CorrectedValue`
3. Never overwriting AI history silently
4. Provenance tracks all human actions with timestamps

### 8.2 Cross-Tenant Isolation

- All queries filtered by `organization_id`
- Verified facts created only from tenant-scoped observations
- No tenant data leaks through fact content

### 8.3 Authorized Verification

- Reviewer must belong to organization
- Observation existence verified before fact creation
- Unique constraint on `observation_id` prevents duplicate facts

### 8.4 IDOR Prevention

- All lookups scoped by `organization_id`
- Reviewer must belong to organization
- Observation existence verified before fact creation

## 9. Limitations

| Limitation | Impact | Future Work |
|------------|--------|-------------|
| Verified facts created only on accept/correct | Rejected/dismissed observations do not create facts | Configurable fact creation rules |
| No fact deduplication | Duplicate verified facts possible | Deduplication by input hash |
| No confidence thresholds | Low-confidence observations create facts | Configurable confidence filters |
| Single reviewer per fact | No multi-reviewer consensus | Multi-reviewer workflow |
