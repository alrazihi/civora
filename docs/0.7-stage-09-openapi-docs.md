# Stage 9: OpenAPI Spec Documentation for Evidence & Document Endpoints

## Status: Complete

## Overview
Stage 9 adds OpenAPI/OpenAPI 3.0 specification documentation for all evidence and
document management endpoints, including schemas for the EvidenceDocument resource.

## Changes

### 1. New OpenAPI Endpoints
**File:** `api/openapi/openapi.yaml`

Added 4 new API path definitions:

1. **POST `/organizations/{orgId}/evidence/{evidenceId}/upload`** — Upload a document
   - Multipart/form-data request body with `file` (binary) and optional `metadata`
   - Returns 201 with EvidenceDocument + storage metadata

2. **GET `/organizations/{orgId}/evidence/{evidenceId}/documents`** — List documents
   - Query params: `page`, `per_page`
   - Returns paginated list of EvidenceDocument objects

3. **GET `/organizations/{orgId}/evidence/{evidenceId}/document`** — Download a document
   - Returns binary file content with Content-Disposition, Content-Type, Content-Length,
     and X-Checksum-Sha256 headers

4. **DELETE `/organizations/{orgId}/evidence/{evidenceId}/documents/{documentId}`** — Delete a document
   - Returns 204 No Content on success

### 2. New Schemas
**File:** `api/openapi/openapi.yaml`

Added 2 new component schemas:

- **`EvidenceDocument`** — The document resource representation:
  - `id`, `evidence_id`, `file_name`, `content_type`, `size_bytes`, `checksum`
  - `uploaded_by`, `uploaded_at`, `created_at`
  - `storage_key` marked as `readOnly` (internal only)

- **`UploadDocumentMeta`** — Metadata returned after upload:
  - `storage_key` — server-generated storage key
  - `upload_url` — presigned URL (nullable, for future use)

### 3. Bug Fix — YAML Structure
**File:** `api/openapi/openapi.yaml:5634`

Fixed a YAML structure issue where the Assessments POST endpoint was incorrectly
nested inside the Documents DELETE endpoint path, causing Redocly to report
"path parameter not defined" errors. Added the missing path declaration:
`  /organizations/{orgId}/assessments:`
