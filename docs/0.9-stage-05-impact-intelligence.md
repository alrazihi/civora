# Stage 5: Impact & Outcome Intelligence

## Goal

Distinguish **activity** from **outcome** from **impact** using only existing authoritative CIVORA data. The system must never invent social impact claims or program effectiveness statements that are not directly supported by recorded case, assistance, follow-up, evidence, and decision data.

## Core Distinction

| Category | Meaning | Example |
|---|---|---|
| **Activity** | Records created or initiated | "10 cases opened" |
| **Outcome** | Completed or achieved states | "6 cases completed" |
| **Impact** | Rates or ratios derived from activity and outcome | "60.0% case completion rate" |

A claim such as "the program reduced poverty by 20%" is **not** generated unless CIVORA possesses appropriate evidence. CIVORA only reports measurable operational outcomes and derived rates.

## Metric Definitions

All metrics are derived from existing tables: `cases`, `assistance`, `follow_ups`, `evidence`, and `decisions`.

### Activity Metrics

| Metric Name | Label | Source | Description |
|---|---|---|---|
| `cases_created` | Cases Created | `cases.created_at` | Total cases opened in the period |
| `assistance_created` | Assistance Created | `assistance.created_at` | Assistance records opened |
| `follow_ups_scheduled` | Follow-ups Scheduled | `follow_ups.scheduled_date` | Follow-up appointments scheduled |
| `evidence_submitted` | Evidence Submitted | `evidence.created_at` | Evidence items uploaded to cases |
| `decisions_made` | Decisions Made | `decisions.decided_at` | Total human decisions recorded |

### Outcome Metrics

| Metric Name | Label | Source | Description |
|---|---|---|---|
| `cases_completed` | Cases Completed | `cases.status = 'CLOSED'` | Cases moved to a closed terminal state |
| `cases_rejected` | Cases Rejected | `cases.status = 'REJECTED'` | Cases closed with a rejected status |
| `cases_needing_information` | Cases Needing Additional Information | `decisions.decision = 'NEEDS_MORE_INFORMATION'` | Cases with a decision requesting more information |
| `assistance_completed` | Assistance Completed | `assistance.status = 'COMPLETED'` | Assistance records marked as completed |
| `follow_ups_completed` | Follow-ups Completed | `follow_ups.completed_date IS NOT NULL` | Follow-up appointments marked as completed |
| `evidence_verified` | Evidence Verified | `evidence.verification_status = 'VERIFIED'` | Evidence items verified by staff |
| `decisions_approved` | Decisions Approved | `decisions.decision = 'APPROVED'` | Decisions with an approved outcome |

### Impact Metrics

| Metric Name | Label | Calculation | Description |
|---|---|---|---|
| `case_completion_rate` | Case Completion Rate | `cases_completed / cases_created` | Share of opened cases that were completed |
| `case_rejection_rate` | Case Rejection Rate | `cases_rejected / cases_created` | Share of opened cases that were rejected |
| `information_request_rate` | Information Request Rate | `cases_needing_information / cases_created` | Share of opened cases that needed more information |
| `assistance_completion_rate` | Assistance Completion Rate | `assistance_completed / assistance_created` | Share of assistance records completed |
| `follow_up_completion_rate` | Follow-up Completion Rate | `follow_ups_completed / follow_ups_scheduled` | Share of scheduled follow-ups completed |
| `evidence_verification_rate` | Evidence Verification Rate | `evidence_verified / evidence_submitted` | Share of submitted evidence verified |
| `decision_approval_rate` | Decision Approval Rate | `decisions_approved / decisions_made` | Share of decisions that were approved |

## Backend Changes

### Domain

`internal/operations/domain/impact.go`

- `OutcomeCategory` type with constants: `activity`, `outcome`, `impact`
- `OutcomeMetric` struct with category, name, label, description, counts, impact value, unit
- `ImpactIntelligenceReport` struct containing a slice of `OutcomeMetric`
- `ImpactRepository` and `ImpactService` interfaces

### Infrastructure

`internal/operations/infrastructure/postgres/impact_repository.go`

- `GetImpactIntelligenceReport` on `PostgresMetricsRepository`
- Queries use `COUNT(*) FILTER (WHERE ...)` for efficient single-pass aggregation
- All queries scoped by `organization_id` and time bucket
- Impact rates computed only when denominator > 0

### Application

`internal/operations/application/impact_service.go`

- `ImpactService` with `GetImpactIntelligenceReport`
- Stamps `CalculatedAt` on the report

### API

`internal/operations/api/impact_handler.go`

- `ImpactHandler` with `RegisterRoutes`
- `GET /organizations/{orgId}/operations/impact/report`
- Query parameters: `period` (daily/weekly/monthly), `bucket` (date-time)
- Uses existing `authMiddleware` and `RequireSameTenant`

### Wiring

`cmd/civora/main.go`

- Instantiates `ImpactService` and `ImpactHandler`
- Registers impact routes on the server router

### OpenAPI

`api/openapi/openapi.yaml`

- Added `OutcomeCategory`, `OutcomeMetric`, `ImpactIntelligenceReport` schemas
- Added `/organizations/{orgId}/operations/impact/report` path

## Authorization and Tenant Isolation

- All impact endpoints require authentication via `authMiddleware`
- Tenant isolation enforced by `middleware.RequireSameTenant`
- All queries scoped to `organization_id`
- No cross-tenant data exposure
