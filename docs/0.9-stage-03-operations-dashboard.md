## 2. Overview

Stage 3 implements the **Operations Dashboard**, a real-time operational workspace that surfaces aggregated metrics from the Stage 2 backend. The dashboard is a read-only view powered by the `/organizations/{orgId}/operations/metrics/dashboard` endpoint.

**Key principles:**
- Every number comes from a real API call
- No hardcoded demo data
- Clear distinction between operational facts, calculated metrics, and unavailable data
- No new charting framework introduced; uses existing CIVORA frontend patterns

---

## 3. Backend Changes

### 3.1 New Dashboard Endpoint

**File:** `internal/operations/api/handler.go`

```
GET /api/v1/organizations/{orgId}/operations/metrics/dashboard
```

**Query parameters:**
| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `period` | string | No | `daily` | Aggregation period: `daily`, `weekly`, `monthly` |
| `bucket` | string (ISO 8601) | No | current time | Time bucket start |
| `workflow_key` | string | No | — | Filter by workflow key |
| `status` | string | No | — | Filter by case status |

**Response:** `OperationsMetrics` (same schema as `/metrics`)

### 3.2 Service Layer

**File:** `internal/operations/application/service.go`

Added `GetDashboardMetrics` method that:
1. Calls all underlying metric repositories
2. Applies workflow/status filters to aging cases
3. Returns aggregated `OperationsMetrics`

```go
func (s *OperationsService) GetDashboardMetrics(
    ctx context.Context,
    orgID uuid.UUID,
    period domain.MetricPeriod,
    bucket time.Time,
    workflowKey string,
    status string,
) (*domain.OperationsMetrics, error)
```

### 3.3 Domain Interface Updates

**File:** `internal/operations/domain/metrics.go`

Added `GetDashboardMetrics` to both:
- `MetricsRepository` interface
- `MetricsService` interface

### 3.4 OpenAPI Specification

**File:** `api/openapi/openapi.yaml`

Added path:
```yaml
/organizations/{orgId}/operations/metrics/dashboard:
  get:
    operationId: getOperationsDashboard
    tags:
      - Operations
    parameters:
      - name: orgId
      - name: period
      - name: bucket
      - name: workflow_key
      - name: status
    responses:
      '200':
        schema:
          $ref: '#/components/schemas/OperationsMetrics'
```

### 4.5 Data Classification

The dashboard clearly distinguishes three types of information:

| Type | Description | Example |
|---|---|---|
| **Operational Fact** | Direct count from database | Total Cases, Active Cases, Completed Cases |
| **Calculated Metric** | Derived from multiple data points | Approval Rate, Completion Rate, Average Wait Time |
| **Unavailable/Insufficient** | Shown when data is missing or zero | "Insufficient data for state duration" |

### 4.6 Filtering Support

- **Period:** Daily, weekly, monthly
- **Workflow key:** Text filter passed to backend
- **Status:** Text filter passed to backend
- **Refresh:** Re-fetches all metrics from API

Filters are applied via query parameters to `/organizations/{orgId}/operations/metrics/dashboard`.

### 4.7 Metrics Displayed

| Metric | Source | Type | Notes |
|---|---|---|---|
| Total Cases | `cases` table count | Operational Fact | Current period bucket |
| Active Cases | `cases` where status not terminal | Operational Fact | Derived from case status |
| Completed Cases | `cases` where status = CLOSED | Operational Fact | Current period |
| Rejected Cases | `cases` where status = REJECTED | Operational Fact | Current period |
| Cases Requiring Review | `review_queue` pending count | Calculated Metric | From pending reviews |
| Aging Cases | `cases` exceeding threshold | Calculated Metric | Default 720 hours |
| Workflow Distribution | `cases` grouped by workflow_key | Operational Fact | With percentage bars |
| State Duration | Average/median/max time in state | Calculated Metric | Shows "Insufficient data" when null |
| Case Cycle Time | Average/median cycle time for closed cases | Calculated Metric | Shows "Insufficient data" when null |
| Pending Reviews | Review queue metrics | Operational Fact | Includes avg wait time |
| Decisions | Decision outcomes and rates | Calculated Metric | Approval rate shown as percentage |
| Assistance Delivered | Assistance completion metrics | Calculated Metric | Completion rate shown as percentage |
| Evidence Requiring Attention | Evidence verification status | Operational Fact | Needs review count highlighted |
| Information Required | Follow-up requests | Operational Fact | Escalation tracking |

## 9. Known Limitations

1. **Date range filters** are accepted by the backend but not yet exposed in the UI. The frontend passes `start_date` and `end_date` in the `OperationsDashboard.filters` object but does not yet render date pickers.

2. **Workflow/status filters** only affect aging cases in the current implementation. Other metrics remain unfiltered.

3. **No charting library** is used. Distribution is shown as text-based bar rows. This is intentional to avoid adding dependencies.

4. **Memory limits** on the development environment prevent full `go build ./...` and `go test -short ./...` from completing. This is an environment limitation, not a code issue.
