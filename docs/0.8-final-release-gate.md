## 3. Critical Blocker Resolution

### 3.1 RESOLVED: ReviewObservation Did Not Auto-Create VerifiedFact

**Finding:** At HEAD `0b4b8a9`, the `ReviewObservation` handler accepted/rejected observations but did not persist a `VerifiedFact` for ACCEPTED actions.

**Fix:** Commit `f13273a` wires `aiVerifiedFactRepo` in `cmd/civora/main.go` and auto-creates a `VerifiedFact` record when observations are ACCEPTED or CORRECTED. The helper `createVerifiedFactInTx` ensures atomicity within the database transaction.

**Evidence:** `internal/ai/application/service.go`, `cmd/civora/main.go`

### 3.2 RESOLVED: OpenAPI Spec Incomplete

**Finding:** The OpenAPI spec at `0b4b8a9` was missing schemas and endpoints for DocumentAnalysis, VerifiedFact, and CaseContext.

**Fix:** Commit `d0b688b` adds:
- Schemas: `VerifiedFact`, `DocumentAnalysis`, `DocumentAnalysisRequest`, `CaseContext`, `Fact`, `AuthorizationEntry`, `ContextBuildRequest`
- Updated `AIObservation` schema: all 7 observation types, `case_id`, `statement`, `source_references`, `created_by`, `status`
- Paths: `/documents/{documentId}/analysis` (generate/list/accept/reject), `/verified-facts` (evidence-level and case-level), `/context` (build/latest/get)

**Validation:** `npx @redocly/cli lint api/openapi/openapi.yaml` — **PASS** (no warnings)

### 3.3 RESOLVED: Stage Document Commit Metadata Errors

**Finding:** Stage documents 01-09 contained incorrect commit SHA, commit message, and parent references. Some referenced non-existent commits or feature branches.

**Fix:** Commit `54c84ac` corrects all stage documents to reference the actual HEAD (`54c84ac`), correct parent (`d0b688b`), correct base (`330b7b8`), and correct working tree status.

## 4. AI Boundary Verification

The hostile review confirms the following boundaries are strictly enforced:

| Boundary | Verification |
|---|---|
| AI cannot make decisions | `internal/ai/` contains no decision-making code. Decisions are in `internal/decisions/` |
| AI cannot approve cases | No `ApproveCase` or equivalent in AI module |
| AI cannot reject cases | No `RejectCase` or equivalent in AI module |
| AI cannot transition workflows | No workflow transition code in AI module |
| AI cannot bypass rules | Rules are evaluated in `internal/rules/` without AI involvement |
| Human verification is explicit | `ReviewObservation` requires human reviewer ID and action (ACCEPT/REJECT/CORRECT) |
| AI is not required for core operation | `NoopProvider` is the default when `CIVORA_AI_ENABLED=false`; all core evidence, workflow, rule, and decision operations function independently |

**Evidence:** `cmd/civora/main.go:289` — `aiProvider = aiprovider.NewNoopProvider()` when AI is disabled.
