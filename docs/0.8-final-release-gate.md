## 2. Executive Summary

CIVORA 0.8 introduces a provider-neutral AI observation platform that generates advisory observations from case evidence and context. All AI outputs require explicit human review before becoming verified facts. The AI module is architecturally isolated from decisions, workflow transitions, rules evaluation, and evidence modification.

This gate independently verified Stages 1–9 by inspecting the actual repository at HEAD, running all applicable tests, and attacking the security boundary. One pre-existing evidence-module NULL-scan bug was discovered and fixed. All tests now pass.

## 3. Architecture

The AI module follows CIVORA's modular-monolith / clean-architecture convention:

```
internal/<module>/
├── domain/          # Pure entities, no I/O
├── application/     # Orchestration, transactions, audit
├── api/             # HTTP handlers
└── infrastructure/   # PostgreSQL repos, AI providers, guards, sanitizers
```

**AI modules:**

| Module | Role |
|---|---|
| `internal/ai/` | Evidence-level and case-level AI observations |
| `internal/casesummary/` | Case summarization grounded in case context |
| `internal/documentintelligence/` | Document-level classification, extraction, summarization |
| `internal/casecontext/` | Authorized case-context assembly for AI grounding |

**Core pipeline:**

```
Documents → Evidence → AI Observation → Human Verification → Verified Fact
    → (advisory only, never auto-fed to rules/decisions/workflow)
```

## 5. Provider Abstraction

**Interface:** `internal/ai/application/service.go`

```go
type AIProvider interface {
    GenerateObservations(ctx context.Context, req ProviderRequest) ([]ObservationResult, error)
    ProviderInfo() domain.ModelInfo
}
```

**Implementations:**

| Provider | Protocol | Default |
|---|---|---|
| `OpenAIProvider` | OpenAI Chat Completions (`/chat/completions`) | No (needs API key) |
| `LocalProvider` | Wraps `OpenAIProvider` with `SkipAuth`; Ollama/llama.cpp compatible | No |
| `NoopProvider` | Returns `ErrProviderDisabled` | **Yes (AI off by default)** |

**Key properties:**
- No third-party AI SDK in `go.mod` — providers use only `net/http`, `encoding/json`, `crypto/sha256`
- Provider-specific types never cross the domain boundary
- `ModelInfo` (name/version/provider) is the only model metadata retained
- Timeout handling: OpenAI 60s, Local 120s, configurable via `http.Client`
- Malformed responses: `PromptInjectionGuard` validates JSON structure and rejects injection patterns
- Configuration security: API keys loaded from env at startup only; never stored in DB

## 6. Grounding / Provenance

**Input grounding:**
- `DocumentContentProvider` retrieves actual document bytes through the evidence service (tenant-scoped, audited)
- Case context (`CaseContextService`) assembles facts from authorized sources only
- `computeInputHash` = SHA-256 of document IDs + filenames + content types + checksums + content + types + max_tokens

**Output provenance (per observation/analysis/summary):**

| Field | Purpose |
|---|---|
| `input_hash` | Reproducibility — identifies exact inputs |
| `output_hash` | Tamper detection — SHA-256 of raw provider response |
| `model` | `ModelInfo{Name, Version, Provider}` |
| `source_references` | Links to evidence, forms, documents |
| `statement` | Human-readable observation text |
| `confidence` | Model confidence (0.0–1.0) |
| `created_at` | Server UTC timestamp |
| `reviewed_at` / `reviewed_by` / `review_notes` | Human review audit trail |

**Verified facts** (`ai_verified_facts`) preserve:
- `original_value` — unmodified AI output
- `corrected_value` — human corrections (if any)
- `provenance` — source, verified_by, verified_at, model, references

## 7. Human Verification

**Observation lifecycle:**
```
OPEN → ACCEPTED → VerifiedFact created (HUMAN_ACCEPTED)
    → REJECTED
    → CORRECTED → VerifiedFact created (HUMAN_CORRECTION)
    → DISMISSED
```

**Verified fact creation:**
- Triggered automatically when observation is ACCEPTED or CORRECTED
- Requires explicit human `ReviewerID`
- Atomic within database transaction (`withTx` + `RecordAuditEventInTx` + `SaveTx`)
- Source tracking: `AI_OBSERVATION`, `HUMAN_ACCEPTED`, `HUMAN_CORRECTION`

**Review actions:** Accept, Reject, Correct, Dismiss — all require human actor.

## 8. Security

### 8.1 Tenant Isolation

Verified at four layers:
1. **Middleware:** `RequireSameTenant` — JWT `organization_id` must match URL `{orgId}`
2. **Service:** `userChecker.BelongsToOrganization` on every operation
3. **Repository:** All queries scope by `organization_id`
4. **Database:** Foreign keys to `organizations(id) ON DELETE CASCADE`

### 8.2 Authorization

All AI endpoints require:
- `AuthRequired` — valid JWT bearer token
- `RequireSameTenant` — org scoping
- `RequireAnyRole("admin", "staff")` — authorized role

### 8.3 Prompt Injection

- **System prompt** instructs model to treat document content as data, not instructions
- **Response validation** via `PromptInjectionGuard`:
  - Strips non-JSON wrappers
  - Validates JSON structure
  - Rejects responses containing injection patterns ("ignore previous instructions", "jailbreak", etc.)
  - Rejects observations with suspicious keys (`instruction`, `command`, `system`, `prompt`, `override`)

### 8.4 PII Protection

- `RedactingSanitizer` redacts SSN, credit cards, emails, phone numbers from text-like content before provider calls
- Binary content (PDF, images) passed through unchanged (documented limitation)
- PII sanitization is mandatory in production wiring (`piiSanitizer(cfg)` in `main.go:394`)

### 8.5 Document Security

- `Document.StorageKey` is `json:"-"` — never exposed to clients
- Document retrieval enforces tenant scoping via evidence service
- Checksum validation on retrieved content
- Document content capped at 100KB before sending to provider

### 8.6 Audit Integrity

- All AI operations recorded in `audit.audit_events` with SHA-256 hash chain
- Audit events and domain writes are atomic within database transactions
- AI-specific actions: `ai.observations_generated`, `ai.observation.created`, `ai.observation.accepted`, `ai.observation.rejected`, `ai.observation.corrected`, `ai.observation.dismissed`, `ai.observation.failed`, `ai.verified_fact.created`, `document_analyses_generated`, `document_analysis.created`, `document_analysis.accepted`, `document_analysis.rejected`, `case_summary.generated`, `case_context.built`

### 8.7 Security Tests

Integration tests cover:
- Cross-tenant review access
- Cross-tenant decision via review
- IDOR review access
- Unauthorized reviewer access
- Unauthorized decision creation
- Reviewer impersonation
- Replay decision request
- Duplicate decision submission
- Concurrent decisions
- Concurrent review assignment
- Stale review
- Workflow transition bypass
- Frontend-only authorization
- Malformed decision payload
- Oversized payload
- Tampered rule results/versions/form versions
- Historical decision mutation
- Audit manipulation
- Sensitive info leakage
- Error leakage

- **Tenant separation:** All queries scoped by `organization_id`

## 13. Known Limitations

| Limitation | Impact | Status |
|---|---|---|
| No per-organization AI rate limits or budgets | Medium — authenticated user can trigger unlimited AI generations | Documented; acceptable for 0.8 |
| No application-layer timeout on provider calls | Medium — provider slowdown could hang requests | Documented; acceptable for 0.8 |
| Malicious filenames not neutralized in AI prompts | Low — filename is metadata, not instruction | Documented; acceptable for 0.8 |
| `MaxObservationContentSize` not enforced in domain | Low — observations could exceed intended size | Documented; acceptable for 0.8 |
| Confidence range not validated in domain | Low — malformed observation could have out-of-range confidence | Documented; acceptable for 0.8 |
| Binary document PII not redacted | Medium — PII in PDFs/images not redacted before provider calls | Documented; requires OCR pipeline in future |
| No prompt template versioning | Medium — prompts are hardcoded strings | Documented; acceptable for 0.8 |
| No circuit breaker / retry for provider failures | Medium — immediate failure on provider error | Documented; acceptable for 0.8 |
| Evidence `verification_reason` / `verification_method` NULL scan | **FIXED** — was causing `TestRegression_CompletedCaseRetainsDomainData` failure | Fixed in `internal/evidence/infrastructure/postgres/evidence_repository.go` |
