# Stage 4: Document Listing & Download Auditing

## Status: Complete

## Overview
Stage 4 implements document listing (GET all documents for an evidence record) and
download audit events. Builds on Stage 3's document storage foundation.

## Changes

### 1. Repository Interface — `ListDocuments`
**File:** `internal/evidence/domain/repository.go:30`

Added `ListDocuments(ctx, orgID, evidenceID, limit, offset) ([]*Document, int, error)`
to the `EvidenceRepository` interface. Returns all documents attached to a given
evidence record with pagination and total count.

### 2. Postgres Implementation
**File:** `internal/evidence/infrastructure/postgres/evidence_repository.go`

`ListDocuments` queries `evidence_documents` filtered by `organization_id` and
`evidence_id`, ordered by `created_at DESC`, with LIMIT/OFFSET pagination. A separate
COUNT query provides the total. No new migration needed — the existing
`idx_evidence_docs_evidence` index on `evidence_documents(evidence_id)` already
supports efficient listing.

### 3. Service Layer
**File:** `internal/evidence/application/service.go`

- Added `ListDocumentsParams` struct (OrganizationID, EvidenceID, DownloaderID, Limit, Offset)
- Added `ListDocuments` service method with:
  - Downloader validation (must belong to org)
  - Evidence existence check
  - Default limit (50) and max limit (200)
  - Pagination offset clamping

### 4. Download Audit Events
**File:** `internal/evidence/application/service.go:510`

`GetDocumentStream` now records an `evidence.document_downloaded` audit event
(via `s.auditor.RecordEvent`) on every successful download, including:
- Resource ID (document ID)
- Evidence ID, filename, content type, size, checksum in metadata

### 5. API Handler
**File:** `internal/evidence/api/handler.go`

- Added `ListDocuments` to the `EvidenceService` interface
- Added `GET /api/v1/organizations/{orgId}/evidence/{evidenceId}/documents` route
- Added `ListDocuments` handler with pagination, org-scoped access control, and
  JSON response via `serializeDocument`
