## 1. Overview

This document describes the AI-assisted case summarization capability implemented in Stage 5 of CIVORA 0.8. The system generates a reviewer-facing summary that aggregates case information with clear provenance distinctions between FACT, SOURCE, AI_OBSERVATION, RULE_RESULT, and HUMAN_DECISION.

## 2. Supported Operations

| Operation | Description | Human Review Required |
|-----------|-------------|----------------------|
| **FULL_SUMMARY** | Generate complete case summary across all sections | Yes |
| **SITUATION** | Summarize case background and context | Yes |
| **RELEVANT_INFORMATION** | List key facts relevant to the case | Yes |
| **IMPORTANT_EVIDENCE** | Highlight critical evidence items | Yes |
| **MISSING_INFORMATION** | Identify gaps in case data | Yes |
| **POTENTIAL_INCONSISTENCIES** | Flag conflicting information | Yes |
| **RULE_EVALUATION_RESULTS** | Summarize rule evaluation outcomes | Yes |
| **WORKFLOW_HISTORY** | Summarize workflow transitions | Yes |
| **PREVIOUS_ACTIONS** | Summarize previous case actions | Yes |
| **AI_OBSERVATIONS** | Summarize AI-generated observations | Yes |

All summaries are AI-generated and stored with `status = PENDING_REVIEW`. They require explicit human **Accept** or **Reject** before being considered final.

## 4. Summary Schema

### 4.1 CaseSummary Entity

```go
type CaseSummary struct {
    ID             uuid.UUID
    OrganizationID uuid.UUID
    CaseID         uuid.UUID
    Type           SummaryType       // FULL_SUMMARY, SITUATION, etc.
    Source         AnalysisSource    // AI_MODEL, HUMAN
    Status         SummaryStatus     // PENDING_REVIEW, ACCEPTED, REJECTED
    Model          *ModelInfo        // name, version, provider
    Content        SummaryContent    // Structured summary sections
    Confidence     *float64          // 0.0-1.0
    InputHash      string            // SHA-256 of case context
    OutputHash     string            // SHA-256 of AI response
    SchemaVersion  string            // "1.0"
    TokenEstimate  int               // Estimated token count
    CreatedAt      time.Time
    CreatedBy      *uuid.UUID        // nil = AI-generated
    ReviewedAt     *time.Time
    ReviewedBy     *uuid.UUID
    ReviewNotes    string
}
```

### 4.2 SummaryContent Sections

```go
type SummaryContent struct {
    Situation                     []SummaryClaim
    RelevantInformation           []SummaryClaim
    ImportantEvidence             []SummaryClaim
    MissingInformation            []SummaryClaim
    PotentialInconsistencies      []SummaryClaim
    RuleEvaluationResults         []SummaryClaim
    WorkflowHistory               []SummaryClaim
    PreviousActions               []SummaryClaim
    AIObservations                []SummaryClaim
}
```

### 4.3 SummaryClaim with Provenance

```go
type SummaryClaim struct {
    Text       string             // The claim text
    Provenance ClaimProvenance    // FACT, SOURCE, AI_OBSERVATION, etc.
    References []SourceReference  // Source references for grounding
    Confidence *float64           // Only for AI_OBSERVATION claims
}
```

### 4.4 Provenance Types

| Provenance | Description |
|------------|-------------|
| **FACT** | Information directly stated in case data |
| **SOURCE** | Information extracted from evidence/document |
| **AI_OBSERVATION** | AI inference/analysis (includes confidence) |
| **RULE_RESULT** | Information from rule evaluation |
| **HUMAN_DECISION** | Information from human decision |
| **WORKFLOW_HISTORY** | Information from workflow transitions |

### 4.5 Validation Rules

- `OrganizationID`, `CaseID` required (non-nil UUID)
- `Type` must be one of the 10 allowed summary types
- `Confidence` must be in range [0.0, 1.0] if present
- `Content` size ≤ 500,000 bytes
- `SchemaVersion` defaults to "1.0"
- `Status` defaults to `PENDING_REVIEW`
- `Source` defaults to `AI_MODEL`
- `ReviewNotes` max length 5,000 characters

## 6. Security

### 6.1 Authorization

All endpoints require:
1. `AuthRequired` — valid JWT
2. `RequireSameTenant` — JWT org_id matches URL org_id
3. `RequireAnyRole("admin", "staff")` — authorized role
4. Service-layer `UserChecker.BelongsToOrganization` — double-check

### 6.2 Tenant Isolation

- All database queries scoped by `organization_id`
- Case context built only from tenant-scoped facts
- No cross-tenant data leakage possible

### 6.3 Prompt Injection Mitigations

- System prompt explicitly forbids following document instructions
- Case context is structured data, not free text from documents
- AI outputs are validated against schema before persistence
- All AI claims tagged with provenance (never treated as facts)

```sql
CREATE TABLE IF NOT EXISTS case_summaries (
    id UUID PRIMARY KEY,
    organization_id UUID NOT NULL,
    case_id UUID NOT NULL,
    summary_type TEXT NOT NULL,
    source TEXT NOT NULL,
    status TEXT NOT NULL,
    model JSONB,
    content JSONB NOT NULL,
    confidence DOUBLE PRECISION,
    input_hash TEXT NOT NULL,
    output_hash TEXT NOT NULL,
    schema_version TEXT NOT NULL,
    token_estimate INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    reviewed_at TIMESTAMPTZ,
    reviewed_by UUID,
    review_notes TEXT,
    FOREIGN KEY (organization_id) REFERENCES organizations(id) ON DELETE CASCADE,
    FOREIGN KEY (case_id) REFERENCES cases(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_case_summaries_org_case
    ON case_summaries(organization_id, case_id);

CREATE INDEX IF NOT EXISTS idx_case_summaries_status
    ON case_summaries(status);
```
