## 4. Capabilities

- **Evidence CRUD**: Create, read, list by case, update metadata
- **Document storage**: Upload (multipart), download (streaming by document ID), list, delete
- **Storage**: Local filesystem provider with server-generated keys, checksum, size validation
- **Verification**: Verify, reject, mark-for-review with immutable history
- **Security**: 10MB size limit, MIME allow-list, filename sanitization, path traversal prevention
- **Audit**: Hash-chained events for all evidence operations

## 5. Security

All 14 security areas verified. No critical or high issues found. Key controls:

- **Tenant isolation**: `RequireSameTenant` middleware + org-scoped queries
- **Authorization**: Role-based (`admin`, `staff`) on evidence endpoints
- **IDOR**: All repository queries filter by `organization_id`
- **Upload**: `SanitizeFileName`, `ValidateContentType`, SHA-256 checksum, 10MB limit
- **Download**: Storage keys never exposed, `sanitizeFilename` on Content-Disposition
- **Path traversal**: `filepath.Clean` + prefix check in `Retrieve`/`Delete`
- **Audit**: Hash-chained, schema-isolated, `VerifyChain` validates integrity

## 6. Privacy

Audit events don't expose storage keys. Personal data minimized. Retention configurable.

## 9. Known Limitations

1. **Delete not fully transactional**: `DeleteDocument` deletes from storage, then DB, then audit — not in a single transaction. If DB delete fails after storage delete, the file is orphaned.
2. **`evidence.reopened` audit action unused**: Defined in migration 0032 vocabulary but no code path produces it.
3. **Spec/implementation mismatches**: `required_evidence` in OpenAPI `WorkflowRequirements` has no Go implementation. Marked as reserved for future use.
4. **Integration/race tests not executed**: No PostgreSQL available in this environment.
